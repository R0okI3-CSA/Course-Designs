## 课程笔记与复习助手 · 项目计划书（技术栈草案）

### 一、技术栈总览

- **开发语言与基础环境**
  - Kotlin
  - Android Studio（最新稳定版）
  - Gradle Kotlin DSL 构建脚本（`build.gradle.kts`）
  - 最低支持版本：Android 8.0（API 26）或以上

- **UI 与设计规范**
  - Jetpack Compose（核心 UI 框架）
  - Material Design 3（`material3` 组件库）
  - 支持浅色 / 深色主题与动态配色
  - 自适应布局（适配不同分辨率与横竖屏）

- **页面结构与导航**
  - 至少 3 个 Activity（如：欢迎/引导页、课程与笔记主界面、复习计划/统计界面）
  - Jetpack Navigation（用于 Activity 内部的多页面导航与返回栈管理）

- **架构与状态管理**
  - MVVM 架构模式
  - Jetpack ViewModel
  - Kotlin Coroutines
  - Kotlin Flow / StateFlow（用于响应式状态与数据流）
  - Repository 模式（数据仓库层：统一封装本地与网络数据）

- **数据持久化与本地存储**
  - Room 持久化库（课程、笔记、复习计划、提醒记录等）
  - DataStore Preferences（轻量级设置：主题模式、提醒开关等）
  - 类型转换器（Room TypeConverter，用于存储复习状态、标签等复杂字段）

- **网络与后端交互**
  - Retrofit（网络请求框架）
  - OkHttp（底层 HTTP 客户端、日志拦截器）
  - JSON 解析库（Moshi 或 Gson）
  - 统一网络数据模型（DTO），与本地实体（Entity）分离
  - （可选加分）自建简单服务器 / Mock 后端（提供课程/知识点模板、备份或同步接口）

- **依赖注入与模块化**
  - Hilt（依赖注入框架）
  - 按功能模块划分包结构（课程管理、笔记管理、复习计划、统计与分析等）

- **系统能力与硬件交互**
  - 本地通知与提醒（Notification + AlarmManager / WorkManager）
  - 系统日历 / 闹钟（可选集成，作为复习提醒补充）
  - 录音能力（用于课堂录音与语音笔记，可选：MediaRecorder / Jetpack Media3）

- **用户体验与设计实现**
  - 加载 / 空数据 / 错误状态统一 UI 组件
  - Snackbar / Dialog 进行错误提示与用户引导
  - 动画与过渡（Compose 动画 API）

- **测试与质量保障**
  - 单元测试（JUnit + Kotlin Coroutines Test）
  - 仓库层/ViewModel 层测试（可选）
  - LeakCanary（可选，用于内存泄漏检测）

- **发布与交付**
  - 支持生成可在真机安装运行的 APK
  - README.md（构建与运行说明）
  - 设计说明书（PDF/Markdown，单独文件）

- **2. 笔记管理模块**
  - **核心版（必须完成）**
    - 笔记列表与基础存储：
      - 使用 RecyclerView 或 Compose 列表展示所有笔记（标题、更新时间、标签等摘要信息）。
      - 支持新建、编辑、删除笔记，数据通过 Room 持久化存储。
    - 文本编辑能力：
      - 在笔记详情页中，用户可以通过手机键盘输入文字内容（类似简化版的文档编辑）。
      - 支持设置笔记标题，正文内容分段显示。
      - 提供基础文字样式选项（如：字号、颜色、粗体/斜体/下划线等）。
    - 标签与分类：
      - 支持为每个笔记设置一个或多个标签（如：课程名、章节名、考试类型）。
      - 支持按标签筛选笔记列表，方便快速定位。
    - 知识点关联（基础版）：
      - 通过「批注 + 知识点」的方式实现知识关联：为某条笔记添加批注时，同时选择或新建一个「知识点」，批注与知识点一一对应。
      - 同一个知识点可以被多条笔记的多条批注引用，形成「一个知识点 ↔ 多个批注/笔记」的关联关系，为后续知识图谱视图打基础。
  - **进阶版（有时间冲刺）**
    - 高级文本编辑：
      - 更细粒度的文字样式控制（多档字号、颜色等）。
      - 仿 Word 的局部格式设置（对选中的部分文字应用样式）。
    - 简易富文本局部格式（当前实现范围）：
      - 采用「段落级」简易富文本模型：将一篇笔记拆分为若干段，每一段记录自身的文字样式（字体、字号、颜色、粗体、斜体、下划线）。
      - 用户在编辑时可以随时切换当前输入样式；当样式发生变化时，系统会将已有输入固化为一个段落，新输入以新的样式单独成段，从而实现「之前输入的文字保持原有样式，新输入使用新的样式」。
      - 简化处理：不支持选中已有文本再修改样式，也不在数据库中精细存储每个段落的样式，只持久化纯文本内容；样式模型的持久化设计作为更高阶的扩展方向保留在进阶版中。
    - 批注与位置关联：
      - 在笔记的某一行或某一段落上添加「批注」，批注内容以小图标或标记形式挂在对应位置，点击后弹出批注卡片。
      - 批注卡片中展示：知识点标题、批注内容（自己的理解/例题说明等）、以及「该知识点在其它笔记中的引用次数」等信息，从而直观表现知识点关联。
    - 手写与画笔功能：
      - 在笔记中增加「手写画布」，支持用户用手指/触控笔进行自由绘制。
      - 将画布作为笔记的一个内容块进行保存与展示。
    - 多媒体扩展：
      - 录音：调用手机麦克风录制课堂音频，并将录音附件添加到某条笔记中。
      - 照片：调用手机相机或相册，将拍摄的板书/资料图片插入到笔记中。
    - 知识点关联进阶版：
      - 在「知识点视图」下，按某个知识点集中展示所有相关笔记，形成简单的知识点聚合视图。
    - 知识导图生成功能（当前实现）：
      - 在笔记的「批注 + 知识点」基础上，为每条批注新增一个「编号」字段，采用层级编号格式（例如：`1`、`1.1`、`1.1.1`），用于描述知识点内部的小分支、小结论。
      - 在笔记详情页添加的批注对话框中，用户可同时填写「知识点标题」「说明」「编号」「批注内容」，编号会与该批注一同保存到本地数据库。
      - 在知识点详情弹窗中（点击某条批注的「详情」按钮），新增「生成知识导图」按钮：
        - 系统会自动收集所有标题相同的批注（可能来自当前笔记或其它笔记），按编号解析为树状结构：如 `1` 为一级节点，`1.1` 为其子节点，`1.1.1` 为更深一层子节点。
        - 在弹出的对话框中使用简化的思维导图样式进行可视化呈现：左侧以短线和圆点表示层级分支，右侧展示「编号 + 批注内容」文本，形成类似「知识点标题 → 1 → 1.1 → 1.1.1 …」的知识结构图。
      - 该功能可以帮助用户用非常轻量的方式，在课堂后快速按照「知识点——分支——细节」的层级关系整理知识结构，并在答辩时展示为一个可视化亮点。

- **5. 自建云端备份服务器（技术加分项）**
  - **目标**
    - 自行开发一个基于 Node.js + Express 的轻量级后端服务，为本应用提供「云端备份 / 恢复」能力，从而满足「自行开发服务器：+10 分」的加分项。
    - 该服务只需支持简单的 JSON 读写，不追求复杂权限与并发，重点展示完整的「App ↔ 自建服务器」数据交互链路。
  - **后端总体设计**
    - 技术栈：Node.js + Express（单文件实现即可，例如 `server/index.js`）。
    - 数据存储方式：
      - 为了降低复杂度，采用「本地 JSON 文件」或「轻量 SQLite」存储云备份数据。
      - 以 `userId` 作为分区键，每个用户只保留最近一次完整备份。
    - 核心接口设计：
      - `POST /api/backup`：
        - 请求体：`{ "userId": Long, "timestamp": Long, "payload": { ...整个应用需要备份的数据... } }`
        - 行为：在服务器端以 `userId` 为键，将 `payload` 写入 JSON 文件（如 `backups/{userId}.json`），若已有旧备份则覆盖。
        - 返回：`{ "success": true }` 或包含错误信息的 JSON。
      - `GET /api/backup?userId=...`：
        - 行为：读取对应用户的最新备份 JSON 并返回。
        - 返回：`{ "success": true, "timestamp": Long, "payload": { ... } }`，若没有备份则返回 `success=false` 并附带原因。
  - **安卓端接入方案**
    - 在应用的 Repository 层增加一个「备份聚合 DTO」：
      - 将当前用户的核心数据（学习计划、笔记、复习提醒等）从 Room 中查询出来，组装为一个统一的 `BackupPayload`（Kotlin data class，可序列化为 JSON）。
    - 新增两个 API 调用方法（可继续使用 `HttpURLConnection` 或引入 Retrofit）：
      - `uploadBackup(userId, payload)`：将 `BackupPayload` 序列化为 JSON，经 `POST /api/backup` 上传到服务器。
      - `downloadBackup(userId)`：调用 `GET /api/backup` 获取 JSON，反序列化为 `BackupPayload`，再批量写回 Room。
    - 在 UI 中增加入口：
      - 在主界面或设置页面添加两个按钮：「上传云备份」「从云端恢复」，分别调用上述两个方法。
      - 调用过程展示加载中 / 成功 / 失败的 UI 状态与 Toast 提示，便于答辩时演示。
  - **Node.js + Express 实现步骤（用于说明书与后续实现）**
    1. 安装 Node.js（从官网下载安装）并在工程根目录创建 `server` 文件夹。
    2. 在 `server` 目录中初始化项目：`npm init -y`。
    3. 安装依赖：`npm install express cors body-parser`。
    4. 编写 `server/index.js`：
       - 创建 Express 应用，启用 `cors` 与 `body-parser.json()`。
       - 实现上述 `POST /api/backup` 和 `GET /api/backup` 两个路由，使用 `fs` 模块读写 `backups/{userId}.json` 文件。
       - 监听如 `http://localhost:3000` 端口，方便在本机测试。
    5. 使用 Postman 或浏览器测试接口：
       - `POST` 发送一份伪造的备份 JSON，确认服务器能正确写入文件。
       - `GET` 请求同一 `userId`，确认能拿到刚写进来的 JSON。
    6. 安卓端在同一 Wi‑Fi 下，修改基地址为局域网 IP（例如 `http://192.168.1.100:3000`），验证真机可以成功上传 / 下载备份。

  - **说明**
    - 本自建服务器的定位是「教学用最小后端」，它不处理用户注册登录，也不做复杂鉴权，只依赖前端传入的 `userId` 做简单隔离，足以体现完整的客户端–服务器交互流程，并满足课程的「自行开发服务器」加分要求。

- **6. 手机号验证码注册与登录（结合自建服务器的扩展功能）**
  - **目标**
    - 在不改变现有「本地用户名 + 密码」账户体系与 Room 登录逻辑的前提下，新增一套「手机号验证码」注册与登录能力，用于对应课程实验中关于网络请求、广播组件/Handler 与验证码登录的要求。
    - 要求：
      - 用户名即手机号（例如中国大陆 11 位手机号），注册时强制按手机号格式校验；
      - 注册时通过自建服务器生成短信验证码并发送（教学环境下以控制台输出 + 接口返回验证码为主）；
      - 登录界面支持在「密码登录」和「验证码登录」之间切换；
      - 验证码登录时由服务器校验验证码是否正确，客户端在通过验证后再在本地标记用户为已登录。
  - **后端接口设计（复用 Node.js + Express 服务）**
    - 在现有 `server/index.js` 中新增两类接口，继续使用 JSON 文件 + 内存结构存储验证码信息：
      - `POST /api/requestSmsCode`：
        - 请求体：`{ "phone": "138xxxxxx" }`。
        - 行为：生成 6 位数字验证码，保存在内存 `smsStore` 中并设置 5 分钟有效期，同时在服务器控制台打印验证码；为了便于调试，还可以在返回 JSON 中附带 `debugCode` 字段。
        - 返回：`{ "success": true, "message": "验证码已生成（教学环境）", "debugCode": "123456" }`。
      - `POST /api/verifySmsCode`：
        - 请求体：`{ "phone": "138xxxxxx", "code": "123456" }`。
        - 行为：根据手机号在内存中查找验证码记录，判断是否存在、是否过期以及是否匹配；验证通过后删除对应记录。
        - 返回：
          - 成功：`{ "success": true, "message": "验证码验证通过" }`；
          - 失败：`{ "success": false, "message": "验证码错误或已过期" }`。
    - 说明：
      - 为了控制复杂度，验证码暂不真正调用第三方短信平台，而是以「控制台输出 + 接口返回」的形式模拟；若后续接入聚合短信等服务，只需在 `requestSmsCode` 中补充真实短信发送逻辑即可。
  - **安卓端注册流程设计**
    - UI 扩展（`AuthActivity` + `AuthViewModel`）：
      - 保留现有用户名/密码/确认密码/昵称等输入框，但将用户名输入框的 label 调整为「手机号（即用户名）」。
      - 在注册模式下新增「验证码」输入框与「获取验证码」按钮：
        - 用户输入手机号后点击「获取验证码」，调用 `POST /api/requestSmsCode` 接口；
        - 请求成功后在界面上给出提示（例如 Toast/错误文本），用户根据控制台或返回值查看验证码并手动输入（教学演示用）。
      - 在 ViewModel 的注册逻辑中增加：
        - 校验用户名是否为合法手机号（使用正则，例如 `^1[3-9]\\d{9}$`）；
        - 校验验证码非空；
        - 在调用本地 `UserRepository.register` 之前，先通过 `POST /api/verifySmsCode` 校验验证码；
        - 仅当服务器返回 `success=true` 时才允许在本地创建用户。
    - 本地账户体系保持不变：
      - 注册成功后仍然在 Room 中创建用户记录，保存密码哈希；
      - 验证码只参与「服务端手机号验证」，不改变本地表结构与已有密码登录逻辑。
  - **安卓端登录流程设计**
    - 登录方式切换：
      - 在登录模式下新增一行切换文本或按钮，实现「密码登录 / 验证码登录」两种方式的切换；
      - 当处于密码登录模式时，界面与现有逻辑完全一致；
      - 当处于验证码登录模式时，隐藏密码输入框，改为显示手机号 + 验证码 +「获取验证码」按钮。
    - 验证码登录流程：
      1. 用户输入手机号，点击「获取验证码」→ 调用 `POST /api/requestSmsCode`，服务器生成并记录验证码。
      2. 用户收到/查看验证码，输入到验证码输入框中。
      3. 点击「登录」按钮时，客户端调用 `POST /api/verifySmsCode` 校验验证码：
         - 若校验失败，直接在界面显示错误信息（不改变本地登录状态）；
         - 若校验成功：
           - 在本地通过 `UserRepository` 根据手机号查找既有用户；
           - 若已注册，则直接将该用户标记为当前登录用户（写入 DataStore）；
           - 若未注册，可提示用户先使用注册流程完成密码设置，或在将来增加「验证码一键注册」扩展。
    - 这样可以保证：
      - 「本地密码登录」与现有逻辑完全兼容；
      - 「服务器验证码登录」作为附加选项满足课程实验要求，并充分利用自建 Node.js 服务。

### 四、开发流程与实现顺序规划

- **阶段 1：基础工程与主题搭建**
  - 搭建单模块工程结构，配置 Compose、Material3、Room、DataStore 等基础依赖。
  - 统一应用主题与配色（蓝白风格），实现主界面的基础框架（标题栏 + 主功能入口占位 + 今日学习新闻占位）。

- **阶段 2：用户体系与数据模型（当前阶段）**
  - 设计多用户场景下的数据模型：
    - 在用户表 `User` 中保存 `id`、`username`、`passwordHash`、`displayName` 等信息。
    - 后续所有核心业务实体（学习计划、笔记、复习提醒等）均包含 `userId` 字段，用于区分不同用户的数据。
  - 实现用户登录相关的底层能力：
    - Room：`UserEntity`、`UserDao`、`AppDatabase`。
    - 密码哈希工具：`PasswordHasher`（使用 SHA-256 对明文密码进行哈希，避免明文存储）。
    - 用户偏好存储：使用 DataStore 保存当前登录用户的 `userId`。
    - 用户仓库层：`UserRepository` 负责注册、登录、获取当前用户等核心操作。
  - 原则：从本阶段开始，所有业务数据访问均以「当前登录用户的 userId」为边界，保证每个用户只看到自己的计划、笔记和提醒。

- **阶段 3：核心业务功能实现（按模块逐步完成）**
  - 学习计划管理模块：
    - 实现 `StudyPlan` 相关的 Room 实体与 DAO（含 `userId`）。
    - 完成「一周课表」视图与学习计划的增删改查，所有查询按当前用户过滤。
  - 笔记管理模块：
    - 实现 `Note` 相关的 Room 实体与 DAO（含 `userId`、标签、知识点关联等字段）。
    - 完成笔记列表与基础编辑界面，支持标签筛选，数据按当前用户隔离。
  - 复习提醒模块：
    - 实现 `ReviewReminder` 相关的 Room 实体与 DAO（含 `userId` 和关联的计划/笔记信息）。
    - 接入本地通知/闹钟，实现提醒的增删改查，并支持从学习计划中一键创建提醒。

- **阶段 4：网络功能与主界面完善**
  - 使用 Retrofit + OkHttp 接入学习资讯/教育新闻接口。
  - 在主界面展示「今日学习新闻」列表或精选内容，并处理加载/错误/空数据状态。

- **阶段 5：进阶功能与优化**
  - 补充高级笔记功能（批注 + 知识点关联、手写、录音、图片）、智能复习建议、多维统计分析等。
  - 优化性能与用户体验，完善异常处理与边界情况处理，准备答辩演示与文档。
