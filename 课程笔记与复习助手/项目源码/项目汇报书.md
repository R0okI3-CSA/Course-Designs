## 课程笔记与复习助手（CourseReviewPlanner）· 项目汇报书

### 一、项目简介
本项目是一款面向学生的学习管理 App，围绕“**学习计划—笔记记录—复习提醒**”形成闭环：把分散的课程信息统一管理，帮助用户按计划学习、快速记录与整理知识点，并通过提醒机制提高复习执行力。

### 二、解决的问题与目标客户（≤300字）
学生常面临学习计划混乱、笔记分散、复习不及时等问题：课程多、任务多导致安排困难；笔记碎片化难检索；复习容易遗忘且缺少提醒。本项目提供计划管理、笔记管理与复习提醒的一体化入口，并支持云同步降低数据丢失风险。
目标客户为在校学生（大学生/研究生）及备考、自学人群，尤其适合需要同时管理多门课程、长期复习与整理知识体系的用户。

### 三、功能结构（功能模块树）
- **0. 用户与入口**
  - 登录/退出（进入主界面前完成身份校验）
  - 侧边栏：显示用户昵称/账号、修改昵称、云同步、头像选择
- **1. 首页（Dashboard）**
  - 今日新闻：拉取并轮播展示
  - 今日计划：汇总当天学习事项（数量/时长/剩余时长）
  - 今日剩余学习时间：以分钟维度展示
  - 上次打开笔记：一键回到最近阅读/编辑内容
  - 四大功能入口（方形按钮栅格）：
    - 学习计划
    - 笔记管理
    - 复习提醒
    - 使用说明
- **2. 学习计划管理**
  - 标签/分组（新建、重命名、删除）
  - 学习计划（新建、重命名、删除、列表展示）
  - 计划详情页：进入单个计划的具体内容管理（时间格/课程安排/自定义事件等）
  - 顶部刷新按钮：刷新当前列表/顺序
- **3. 笔记管理**
  - 标签/分组（新建、重命名、删除）
  - 笔记（新建、重命名、删除、列表展示）
  - 笔记详情页（核心编辑能力）：
    - 文本编辑与样式（段落/格式等）
    - 图片插入（拍照/相册）
    - 录音插入与播放
    - 画笔涂鸦/板书式记录
    - 知识点/批注扩展与知识导图（结构化整理亮点）
  - 顶部刷新按钮：刷新当前列表/顺序
- **4. 复习提醒管理**
  - 标签/分组（新建、重命名、删除）
  - 提醒（新建、删除、启用/禁用、列表展示）
  - 提醒详情页：编辑提醒内容与触发时间等
  - 通知触发页：到点提醒弹出与跳转
  - 顶部刷新按钮：刷新当前列表/顺序
- **5. 全局导航与一致性体验**
  - 底部导航栏（Home/Plan/Note/Reminder）：主功能页之间快速切换，当前 Tab 高亮
  - “类微信”体验：切换主界面与三大管理界面时底部导航保持固定

### 四、页面结构与交互设计（汇报可讲的点）
- **顶部栏**
  - 首页：左侧头像（打开侧边栏），右侧退出登录
  - 三大管理页：左侧刷新按钮（黑色图标），右侧“+”菜单（新建标签/新建条目）
- **侧边栏**
  - 展示昵称/账号
  - 修改昵称（弹窗输入）
  - 云同步（本地/云端备份同步）
- **信息卡片 + 快捷入口**
  - 首页使用卡片化信息承载“今日新闻/今日计划/剩余学习时间/最近笔记”，中部提供四个大入口按钮，降低学习成本。

### 五、技术架构与实现要点
- **UI**：Jetpack Compose + Material Design 3（`Scaffold`、`CenterAlignedTopAppBar`、`ModalNavigationDrawer`、`NavigationBar`、`Card` 等）
- **架构**：MVVM（ViewModel 维护页面状态，Repository 负责数据访问封装）
- **本地数据**：Room（计划/笔记/提醒等实体持久化），本地 CRUD
- **异步与状态**：Kotlin Coroutines（IO/主线程切换），Compose `remember`/`LaunchedEffect`/生命周期回调刷新
- **网络能力**
  - 今日新闻：HTTP 请求获取并轮播展示
  - 云同步：对接自建备份服务（`server/`），上传/拉取 JSON 备份数据
- **多媒体能力（笔记详情）**
  - 图片：拍照/相册插入并展示
  - 录音：录制并插入笔记内容
  - 画笔：自由绘制辅助记忆

### 六、云同步设计说明（可作为亮点）
- **目标**：降低误删/换机导致的数据丢失，支持跨设备恢复。
- **策略**：对比本地与云端数据量（notes/plans/reminders 数量），决定“上传覆盖”或“下载覆盖”，并对结果做 Toast 提示。
- **数据格式**：JSON（包含 userId、timestamp、payload：notes/studyPlans/reminders）。

### 七、现场演示流程建议（3–5 分钟）
- **1）登录进入首页**：展示顶部栏、侧边栏（昵称/账号/修改昵称/云同步）。
- **2）首页四张信息卡**：新闻轮播、今日计划/剩余时间、最近笔记跳转。
- **3）底部导航切换**：Home → 学习计划 → 笔记管理 → 复习提醒，展示“导航固定”的一致体验与高亮样式。
- **4）学习计划/笔记/提醒模块**：演示“+”新建、左上角刷新、进入详情页。
- **5）笔记亮点**（可选）：插入图片/录音/画笔或知识导图入口（挑一个最稳的演示）。
- **6）云同步**（可选）：演示上传/恢复提示（若网络/服务器稳定）。

### 八、总结与后续迭代方向
- **当前价值**：将计划、笔记、提醒集中在一个 App 内，减少切换成本；首页信息化呈现提升每日执行力；云同步与多媒体笔记提高可靠性与记录效率。
- **后续方向**：更智能的复习策略（间隔重复）、更强搜索与标签体系、知识图谱可视化、以及更细粒度的富文本编辑与多端同步策略优化。

#### 2）技术选型与实现方式（用什么技术、怎么做）
- **Node.js + Express**：提供 REST API（HTTP + JSON）。
- **body-parser + cors**：解析 JSON 请求体、支持跨域访问（便于 App 端直接请求）。
- **fs + path（文件系统持久化）**：将用户备份以 JSON 形式直接写入磁盘文件，实现轻量、可部署、可直观查看的“云端存储”。
- **云备份/云同步 API（核心）**（位于 `server/index.js`）：

- **扩展能力（同一台自建服务器承载）**（位于 `server/index.js`）：
  - **课表分享**：`POST /api/timetable/share`、`GET /api/timetable/:shareId`
  - **自定义计划分享**：`POST /api/customSchedule/share`、`GET /api/customSchedule/:shareId`
  - **手机号验证码（教学演示）**：`POST /api/requestSmsCode`、`POST /api/verifySmsCode`（内存存储 + 5 分钟过期；演示环境可返回 `debugCode`）

#### 3）功能执行逻辑（端到端流程）

##### A. App 端触发（用户点击“云同步”）
- **触发位置**：主页侧边栏按钮（`MainActivity.kt` 中 `triggerCloudSync()`）
- **关键步骤**
  - 获取当前登录用户 `userId`
  - 调用 `BackupRepository.buildPayloadForUser(userId)` 构建本地快照（笔记/学习计划/复习提醒三类核心数据）
  - 请求云端快照：`GET /api/backup?userId=...`
  - 对比本地与云端数据量（notes/plans/reminders 条数总和），决定上传或下载：
    - 云端为空或本地更多 → **上传覆盖云端**
    - 云端更多 → **下载覆盖本地**
    - 相近 → 提示无需同步

##### B. 上传路径（本地 → 云端）
- App：将本地快照序列化为 JSON（包含 `userId/timestamp/payload`）→ `POST /api/backup`
- Server：接收请求并写入 `server/backups/{userId}.json` → 返回 `{ success: true }`
- App：根据结果提示“上传成功/失败”

##### C. 下载路径（云端 → 本地）
- App：`GET /api/backup?userId=...` 获取云端 `payload`
- App：调用 `BackupRepository.restoreFromPayload(userId, payload)` 覆盖恢复本地数据  
  - 简化策略：先删除本地旧数据，再按 payload 重建（并将分组信息按“未分组”处理以降低外键复杂度）
- App：提示“已从云端恢复（覆盖原有数据）”
