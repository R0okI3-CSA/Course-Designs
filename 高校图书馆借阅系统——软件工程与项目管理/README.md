# 📚 高校图书馆借阅系统 (University Library Borrowing System)

> **项目类型**：软件工程课程设计  
> **核心架构**：面向对象分析与设计 (OOA&D) / 结构化分析与设计  
> **系统特性**：全业务闭环管理、悲观锁并发控制、严格 ACID 事务一致性、基于角色的权限隔离  

---

## 📖 项目简介
本项目是一个面向高校环境的标准化图书馆借阅管理系统，旨在对图书信息、馆藏副本、读者账户以及借还书生命周期进行全闭环的高效管理。系统下层构建了稳健的数据管理子系统，通过严格的事务控制与完整性约束，完美实现了“借书—还书—逾期—罚款—缴费—解除限制”的业务流程闭环，保障高频并发场景下的数据安全与可审计性。

---

## ✨ 核心业务与功能模块

系统围绕两大核心角色展开，实现不同角色的业务流转与权限隔离：

### 👨‍💼 管理员功能 (ADMIN)
* **信息维护**：支持对图书信息和读者信息进行全面的查询、增加、修改和删除。
* **借阅与超期管理**：可以实时查询任意读者的借阅情况，并集中查询全局借阅超期的图书信息。
* **账户管理**：支持查询个人信息、重置指定读者的密码以及修改个人密码。

### 👤 读者功能 (READER)
* **图书借还**：支持日常借书与还书操作。
* **借阅追踪**：支持查询个人当前正在借阅及历史的借阅情况。
* **逾期与罚款处理**：支持查询个人超期罚款信息；若存在图书逾期，系统自动限制借阅权限，读者需支付罚款并归还逾期图书后方可继续借书。
* **基础查询**：支持检索图书详细信息、查询个人基本信息以及修改个人密码。

## 🗄️ 数据管理子系统设计

数据管理子系统负责核心数据的持久化、并发安全与高频查询支撑，采用“书目—馆藏副本—借阅记录—罚款—缴费”的严密链路建模。

### 1. 核心数据表结构
* **`user` (用户表)**：依靠 `login_id` 唯一约束处理登录鉴权，记录角色 (`READER`/`ADMIN`) 与账户激活/禁用状态。
* **`book_title` (书目表)**：依靠唯一的 `isbn` 维护图书通用检索属性（书名、作者、出版社等）。
* **`book_copy` (馆藏副本表)**：以条码作为主键，精准管理每本实体书的可借状态 (`AVAILABLE`/`BORROWED` 等) 与物理馆藏位置。
* **`loan` (借阅记录表)**：建立读者与副本的外键关联，记录借还时间及当前借阅状态，作为还书与逾期判定的核心依据。
* **`fine` (罚款表)**：记录由于逾期触发的罚款金额与支付状态 (`UNPAID`/`PAID`)，作为限制借书的核心风控指标。
* **`payment` (缴费表)**：记录缴费流水明细及支付方式；缴清后同步更新罚款状态以解除借书限制。

### 2. 核心 ACID 事务与并发安全
为杜绝高并发环境下的“一册多借”或“还书未生成罚款”等脏数据问题，关键业务操作均强制采用行级悲观锁 (`SELECT ... FOR UPDATE`) 进行一致性保护：
* **借书事务 (`borrowBook`)**：同一事务内严格串行校验读者状态、限制条件（是否存在未缴罚款或逾期未还）及馆藏副本状态，锁定副本后生成借阅记录并扣减可用库存。
* **还书事务 (`returnBook`)**：锁定该副本对应的未归还借阅记录，实时对比归还时间与应还时间；若判定逾期，在归还副本的同时自动原子化插入对应的未缴罚款记录。
* **缴费事务 (`payFine`)**：锁定对应罚款记录并写入缴费流水；确认全额缴清后将罚款置为已缴，系统自动解除该读者的借书风控限制。

### 3. 安全权限与高频查询优化
* **RBAC 权限隔离**：应用层基于 `user.role` 实现读写控制，读者端所有查询接口强制追加 `where reader_id = currentUser` 条件，从底层杜绝越权访问。
* **逻辑删除机制**：书目、副本与用户原则上不进行物理删除，统一采用 `status` 状态字段进行逻辑标记，保障所有历史借阅流水完全可追溯审计。
* **查询索引设计**：针对高频查询热点建立了精确的多字段组合索引，如面向当前/历史借阅查询的 `loan(reader_id, returned_at)`、面向未缴罚款统计的 `fine(status, loan_id)`、面向管理员超期统计的 `loan(due_at, returned_at)`，以及支撑书目模糊检索 和可用库存计算的专属统计方案。
